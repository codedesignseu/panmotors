# Migration plan: Gutenberg + ACF Blocks (D11)

Status: plan, 25 Sep 2026. No block code until approved. Architecture: [`blocks.md`](blocks.md). This file is the how and the order.

Goal: every page is built from blocks, no page reads content from another page, and the homepage looks and behaves exactly as it does now (the current design match of `_design/index.html`).

## 0. Why the homepage lost five sections (cause)

Found 25 Sep 2026, nothing restored yet.

1. `dev/seed.php` runs under WP-CLI with no `--user`, so it created the section pages (Featured Cars 206, About 208, Latest Cars 209, Showroom 211, Contact 212) with `post_author = 0`.
2. `dev/tests/editor-fields.mjs` saved those pages through the block editor as the test Editor `pm-editor-test` (user ID 2). The block editor saves ACF meta boxes by posting the classic form to `post.php`; `_wp_translate_postdata()` sets an empty author to the current user. The five pages became owned by user 2. Home (author 1) and the legal pages (never saved by the test) were not.
3. The cleanup after the test ran `wp user delete pm-editor-test --yes` without `--reassign`. `wp_delete_user()` with no reassign deletes every post of that user whose type is deleted with the user (pages and posts); for pages that means Trash. At 2026-09-25 13:31:11 UTC all five pages and the user's auto-draft (421) went to Trash in the same second.
4. `panmotors_page()` only returns published pages, so every homepage section reading from them rendered nothing. The primary menu items pointing at them disappeared for the same reason.

Evidence: `wp_posts` (status `trash`, author 2, modified 13:31:11), `_wp_desired_post_slug` on each page, `_wp_trash_meta_time` 1790343071 on 421, revision 462 at 13:31:11, user 2 no longer in `wp_users`, the `user delete` command in the previous session's log. `debug.log` has nothing at that second (a deletion is not an error). The seed never trashes these pages: it only deletes `/our-values/` and `/live/` (D10).

The pages and their field data are intact in Trash. What to do with them is in §9.

Lessons, applied below: test users are always deleted with `--reassign=1`; the seed runs with `--user=1`; and (D11) no page depends on another page existing.

## 1. Blocks

ACF Blocks, `block.json` with `apiVersion: 3`, ACF `blockVersion: 3`, `mode: preview`, namespace `pm/`. Each block lives in `blocks/<name>/` (`block.json` + `render.php`). `render.php` only gathers data (block fields, Options, Cars) and passes it as args to the existing view in `template-parts/sections/`, which keeps its markup and classes unchanged and stops reading `page_id`. Field groups are generated by `dev/acf-fields.py`, one group per block, location `block == pm/<name>`. Field keys stay the same where the field is the same (`field_pm_hero_eyebrow` …), so labels, instructions and limits carry over word for word.

Every block: title, one-line description, icon, category "Pan Motors", `example` with seeded-like data for the inserter preview, `supports`: no align, no anchor, no custom class name, no colour/spacing/typography, `multiple` false for hero/marquee/enquire.

Help texts that pointed to other pages (`{edit:about}` …) are rewritten because the content is now in the block itself.

## 2. Cars post type

`pm_car`, "Cars" in wp-admin, registered in `inc/cars.php`. Data store only: `public => false`, `show_ui => true`, `show_in_rest => true` (needed by the relationship field in the block editor), `publicly_queryable => false`, `has_archive => false`, `rewrite => false`, `exclude_from_search => true`, `capability_type => 'page'` (Editors manage it), supports `title`, `page-attributes` (order). No single or archive template, no URL, not in sitemaps (also filtered out of `wp_sitemaps_post_types`). D1 stands: no car pages.

Field group "Car" (location `post_type == pm_car`):

| Field | Limit / rule | Used by |
|---|---|---|
| Photo (ACF image, required) | landscape, at least 1960 × 1102px, keep the car in the centre (it is cropped tall in Featured Cars and 16:9 in Latest Cars) | both |
| Marque | 20, required | Featured |
| Model | 28, required | Featured |
| Reference | 12 ("No. 04") | Featured |
| Detail | 22 | Featured |
| Note | 26 | Featured |
| Link | optional; empty = showcase only | Featured |
| Slider caption | 40 | Latest |
| Place | 20, default "Paphos" | Latest |
| Featured | true/false | Featured ("Cars marked Featured") |
| Order | `menu_order` (page attributes) | Featured order |

The post title is set from marque + model on save, so the Cars list reads well. List columns: photo, marque and model, Featured, date. Latest Cars order = publish date, newest first (the client changes the date to move a car).

Photo is an ACF image field rather than the featured image so the minimum size is enforced. Demo data maps to 6 cars: the 4 featured ones (Porsche, Grand Touring, Ferrari, Track, in that order) plus the McLaren and the red night shot, with dates set so Latest shows the current 6 slides in the current order and captions. The same attachments are used, so `srcset` output is identical.

## 3. Synced pattern

The seed creates a `wp_block` post "Our Values" (synced) containing one `pm/values` block with the three current values, and Home references it with `<!-- wp:block {"ref":ID} /-->`. About uses the same reference once it is built. Editing the pattern once updates both.

The Editor must be able to edit it: `inc/admin.php` currently hides Patterns, so it keeps the menu item hidden but allows `edit.php?post_type=wp_block` and `post.php` for `wp_block` (the "Edit original" button in a page opens it).

## 4. `theme.json` (classic theme, settings only)

`version: 3`, settings only, no `styles`:
- `color`: `custom`, `customGradient`, `defaultPalette`, `defaultGradients`, `defaultDuotone`, `duotone` off, empty palette; `background` off.
- `typography`: `customFontSize`, `fontSizes` empty, `defaultFontSizes`, `lineHeight`, `letterSpacing`, `textTransform`, `textDecoration`, `fontStyle`, `fontWeight`, `writingMode`, `dropCap`, `fluid` off; `fontFamilies` empty; `fontLibrary` off (`fontLibrary` setting plus removing the Fonts screen for Editors as now).
- `spacing`: `padding`, `margin`, `blockGap`, `units` off, `customSpacingSize` off, `defaultSpacingSizes` off.
- `layout`: no `contentSize`/`wideSize`, `allowEditing` off, `allowCustomContentAndWideSize` off; `dimensions`, `border`, `shadow`, `position` off; `appearanceTools` false; `lightbox` off.
- Block-directory and Openverse off through PHP (`remove_action( 'enqueue_block_editor_assets', 'wp_enqueue_editor_block_directory_assets' )`, `block_editor_settings_all` → `enableOpenverseMediaCategory` false). Code editor off for Editors (`codeEditingEnabled` false).

Front-end risk: a `theme.json` makes WordPress print global styles (preset variables, `:where(body){margin:0}`, link underline defaults, layout rules) and stop printing `classic-theme-styles`. The homepage must not change, so on the front end the theme dequeues `global-styles` and `wp-block-library-theme`, keeps `wp-block-library` off pages that have only `pm/*` blocks, and styles the allowed core blocks itself in `main.css`. The `<head>` comparison in §8 proves no new stylesheet or inline style reaches the homepage.

## 5. Allowed blocks and editor behaviour

`allowed_block_types_all` (PHP, per post type):
- Pages: all `pm/*`, `core/block` (synced patterns), `core/heading`, `core/paragraph`, `core/list`, `core/list-item`, `core/image`, `core/quote`, `core/buttons`, `core/button`.
- `wp_block`: the same.
- Rich text formats limited to bold, italic, link (editor JS below). Core block styles and variations for the allowed blocks removed, so the client cannot pick "outline" buttons or rounded images the design doesn't have.
- Pattern directory (`should_load_remote_block_patterns` false) and core patterns (`remove_theme_support( 'core-block-patterns' )`) off. Theme patterns: "Homepage (full design)" (hero, marquee, featured, Our Values reference, about, latest, live, showroom, enquire, seeded wording). One pattern per inner page when designed.
- Home: `pm/hero` carries `"lock":{"move":true,"remove":true}` in its markup. Everything else is free to move and remove.
- No page templates: the page template lock question is closed. Nothing in `templates/` remains, so there is no template to lock or to switch; the only lock is the hero block lock on Home.

Editor CSS (`assets/css/editor.css`, loaded with `main.css` and the fonts into the editor iframe through `enqueue_block_assets`, only when `is_admin()`):
- Canvas background ink, body font, `pm/*` blocks full width (`.wp-block[data-type^="pm/"]` max-width none, margin 0), core text blocks centred at the prose width.
- Reveal: already content-visible without `html.pm-js`, which the editor iframe doesn't get. Guard kept in `editor.css`.
- Hero: fixed height `min(100vh, 900px)` in the editor so the canvas doesn't jump with the viewport.
- Marquee: animation paused.
- About: fade fixed at the dark state (no scroll script in the editor).
- Latest Cars and Showroom: first slide shown, arrows visible but inert; horizontal track can scroll.
- Hover effects stay (they help the client read the design).

Editor behaviour in PHP: `render.php` gets `$is_preview`; in preview the hero and Live videos print the poster `<img>` only (no `<video>`, no autoplay), and no front-end module is enqueued.

Editor JS (`assets/js/editor.js`, plain ES, enqueued on `enqueue_block_editor_assets`, depends on `wp-blocks`, `wp-rich-text`, `wp-dom-ready`): unregister rich text formats other than bold, italic, link; unregister block styles and variations of the allowed core blocks; nothing else. No build step, no JSX.

## 6. Scripts on the front end

`render.php` calls `panmotors_use_module()` when the block renders on the front end, exactly as `panmotors_render_section()` does now, so a module loads only when its block is on the page. Classic themes print script modules in the footer, so enqueueing during `the_content` works (already relied on today).

Hero poster preload (`wp_head`, before blocks render): `panmotors_hero_poster_id()` parses the current page's blocks (`parse_blocks`) and reads `hero_poster` from the first `pm/hero`. Same for `FAQPage` schema from `pm/faq` (inner pages, later).

`the_content` filters that would change the homepage text or images (`wptexturize`, `convert_smilies`, `capital_P_dangit`, `wp_filter_content_tags` re-writing `<img>`) are checked in the HTML diff. Today's section text is printed without them; if any of them changes output, it is removed from `the_content` for pages built from `pm/*` blocks so text stays exactly as typed. `wpautop` is already skipped by core for block content.

## 8. Seed

`wp eval-file dev/seed.php --user=1` (documented in the header; the seed refuses to run without a current user).

1. Field groups from `acf-json` as now; remove the database copies of the seven old groups listed in §7 (only those keys).
2. Media and Options as now (Technical: contact page link only).
3. Cars: six `pm_car` posts from the current featured and latest data (§2), `_pm_demo` flag, matched on a `_pm_seed_key` meta so re-runs update instead of duplicating.
4. Synced pattern "Our Values" (`wp_block`, `_pm_seed_key`), updated in place on re-runs.
5. Home: `post_content` rebuilt as block markup with `serialize_blocks()`. Block data is flattened the way ACF stores it (`hero_eyebrow` / `_hero_eyebrow` → field key; repeaters as `live_posts_0_caption`, `live_posts` = row count). A helper `panmotors_seed_block( 'pm/hero', array( … ) )` reads the field keys from the generated JSON so seed data uses field names only. Old Home post meta from the field-group era is deleted (those keys only).
6. Menus as now; inner pages (Featured Cars, About, Latest Cars, Showroom, Contact) are only created if missing, with a `pm/page-hero` block, and never deleted.
7. Safety: never deletes pages, users, patterns or field groups it did not create; stops if `git status --porcelain acf-json` is not empty.

Result on a fresh install: the same Home as this site.
